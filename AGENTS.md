# Repository guidance

- This is **Joy Pi Board**, not Joy Pi Health. Confirm repository identity before changing files. Preserve existing work.
- **Board presents. Health observes.** No `/proc`, `/sys`, system commands or sensors for metric collection; no imports from Health's Go `internal` packages. Health is read-only.
- Start with [README.md](README.md) and its authority map. Product scope and stable requirement IDs live in [the specification](docs/specification-v0.1.0.md); wire behavior in the [Board](docs/board-api-v0.1.0.md) and [Health](docs/health-integration-v1.0.md) contracts.
- Pin upstream contract changes explicitly through [the evidence record](docs/health-baseline.md). Preserve nulls, exact unsigned 64-bit JSON integers and issue order. Never invent hardware model or health scores.
- Keep established decisions, verified upstream facts and [proposals](docs/decisions.md) distinct. Technical documentation is English. Do not mark planned tests PASS.
- [Sprint 00](docs/sprint-00.md), [Sprint 01](docs/sprint-01.md) and [Sprint 02](docs/sprint-02.md) are closed with separate historical local/CI evidence. The current user implementation instruction authorizes [Sprint 03](docs/sprint-03.md), superseding preparation-only restrictions: dashboard, exact consumer, browser scheduling/freshness, tests, justified development dependencies, scripts/CI and documentation. S03-R01/R02/R04 and the S03 presentation/accessibility and preliminary resource-measurement subset of P-06 are approved by that instruction. S03 closure requires new exact-commit CI and mandatory browser evidence; do not infer it from local tests. S04, physical/compression extensions, packaging and deployment remain unauthorized. No commit, push, tag or release. Preserve Health and S00/S01/S02 evidence.
- Use [foundation commands](docs/s00-foundation.md); build frontend before Go embed. Exact tools are checked by `node scripts/tasks.mjs tools` with implicit Go switching disabled. [ADR-001](docs/adr-001-exact-json-integers.md) adopts Health's numeric convention. S01 tolerates unknown members, rejects decoded duplicate keys and applies the approved size/depth/Unicode rules; these are Board consumption choices. No general-purpose homegrown JSON parser or unused dependency.
- Update cross-references and requirement/test/sprint traceability together. Physical acceptance requires the exact candidate checksum and actual Raspberry Pi 3B+ evidence; mocks cannot satisfy Class C.

## Production envelope consumer

**S03-R01, PROPOSED** consumption choices; approved server and Health rules are unchanged.

### Bounded HTTP acquisition

Fetch only `/api/v1/overview`, GET, no query/body, same-origin mode/credentials, cache no-store, redirect error. No retry or response cache. Use an explicit AbortController/timer (no dependency on newer timeout-combination APIs at the browser floors). Start timing immediately before Fetch; include headers, complete body, validation and eligibility for publication in the proposed 2 s deadline. A timer cannot interrupt synchronous parsing; check elapsed time again afterwards and reject a completion at or beyond 2,000 ms even if the timeout callback was delayed.

Distinguish rejection without an HTTP response (connection failure/timeout), received non-200 (Board HTTP error with status), and HTTP 200 with invalid contract. For non-200, cancel the body and show a fixed local status message; do not parse or display arbitrary server error text. A Health-unavailable HTTP 200 is a usable Board response.

For 200 require application/json, case-insensitive MIME and optional sole UTF-8 charset; reject other/duplicate parameters or comma-joined media types. Require Cache-Control to contain no-store. S02 serves identity: accept absent/identity Content-Encoding, reject other encodings for now; revisit only with S04 transport approval. Optional Content-Length is untrusted: reject an invalid/oversized decimal value early and check actual bytes regardless. Read Response.body through a reader, count received Uint8Array bytes before retaining them, cancel/release/abort at limit+1; retain at most **81,920 bytes**, including whitespace/newline. Browser-internal chunk allocation is not controlled by this bound. Missing stream, empty/truncated body, declared identity length mismatch or read error is a failed response. Never fall back to unbounded text()/arrayBuffer()/json(). Decode once with fatal UTF-8 and preserved BOM for rejection, as in S01; do not replace malformed input.

### Exact parsing without a second Health validator

Recommendation: share the S01 guarded lossless document parser with two fixed profiles (snapshot 65,536 bytes / 32 containers; envelope 81,920 / 34). Default parseSnapshot remains unchanged. The library owns JSON grammar/numbers/trailing-document validation; the guard owns UTF-8/Unicode/duplicates/depth. Private branding must remain unforgeable by `__proto__`, `constructor`, `isLosslessNumber` or other unknown data. Own-property checks are mandatory. No response.json, ordinary numeric JSON.parse, regex JSON rewrite, stringify round trip, global prototype modification or general-purpose owned parser.

The installed lossless-json declarations expose numeric-token and duplicate callbacks, not a general raw-subtree source-range API. To preserve the exact nested snapshot byte budget, extend the existing string/container preflight with a **narrow source-span locator for the object at decoded path /health/snapshot only**. Track root/health member names and object boundaries outside string tokens; match escaped keys by their decoded names. Accept its offsets only after the whole document passes library parsing and structural checks. Do not implement grammar/value decoding or an arbitrary JSON Pointer engine in the locator. Identify the opening/closing braces regardless of property order, whitespace, nested unknown members or marker-like strings; null has no object span. Ambiguous/missing span for a parsed snapshot object is a contract failure, never repaired.

Pass that original substring to **parseSnapshot**, which rechecks its UTF-8 byte count, local depth and the existing schema. Count every byte inside its braces, including internal whitespace; enclosing member whitespace belongs to the envelope. This intentionally parses the bounded snapshot a second time to avoid exporting an unchecked schema validator. It does not duplicate schema rules or reinterpret numeric tokens. Parsed known fields are the UI projection, never a transport re-encoding. Discard the temporary full tree/text after validation. A depth-32 snapshot inside two Board containers is depth 34; a snapshot at depth 33 fails independently. Wrapper whitespace cannot conceal an oversized snapshot. Also enforce the approved wrapper overhead <=1,024 bytes by subtracting original snapshot-span bytes (zero for null) from the complete envelope byte count, including its newline. The 81,920-byte read ceiling is an independent outer bound, not a promise that an otherwise oversized wrapper is valid. Do not count reserialized bytes: optional HTML/Unicode escaping can expand a valid maximum snapshot.

S03-T03 must prove this narrow adapter before UI integration: shuffled/escaped root and health keys; snapshot first/middle/last; nested `health`/`snapshot` names; braces and `"snapshot":` inside strings; prototype-like members; literal/escaped Unicode; duplicate escaped-equivalent keys; 65,536-byte markup case and uint64 extremes. If it cannot preserve exact ranges under these guards, report that concrete conflict before introducing a general parser or relaxing bounds.

### Envelope and age invariants

Require an object with own generated_at and health members; health is a non-null object with own availability, snapshot_state, last_success_at, reason and snapshot. **Proposed Board-envelope unknown policy: reject additional members at the Board root and health wrapper.** Unlike Health schema 1.0's approved tolerance, the versioned Board wrapper is small and fixed; accepting future additions requires an explicit consumer compatibility review. This does not close unknown members inside Health. All subtrees still receive global duplicate/Unicode/depth checks before field interpretation.

Validate Gregorian RFC3339 UTC uppercase Z timestamps, four-digit year 0000–9999, real date/time, optional decimal fraction, no leap seconds/offset/comma. Retain exact strings. Do not infer timestamp ordering: Pi wall changes can reverse generated_at and last_success_at. Board timestamps do not inherit Health's nonzero-time restriction; observed_at continues through S01. No Date.parse-only acceptance or timestamp subtraction for freshness.

| Valid wire combination | last_success_at / snapshot | Header on HTTP 200 |
|---|---|---|
| available / current / reason null | timestamp / valid snapshot object | Required canonical integer, 0..30000 |
| unavailable / stale / one of five approved reasons | timestamp / valid snapshot object | Required canonical integer, 0..30000 |
| unavailable / none / approved reason, no success | null / null | Absent |
| unavailable / none / approved reason, expired success | timestamp / null | Required canonical integer, 30001..9007199254740991 |

Reject every other combination, missing field, type mismatch or enum. Health's unsupported schema in a supplied snapshot is an invalid Board envelope to the UI, not a newly inferred Health reason. Interpret only Board's reason field as its report.

Read X-Joy-Pi-Snapshot-Age-Ms as canonical decimal `0|[1-9][0-9]*`, reject signs, whitespace observable through Fetch, fractions, exponents, leading zeros, comma joining and >9007199254740991. Check lexical length/bounds with bigint before any safe Number conversion; never round before validation. Saturation means expired forever for that view. No header with null success; required header with non-null success, even for none. Fetch exposes normalized header values, not original wire lines: reject comma-joined duplicates; do not claim detection of whitespace already stripped by the browser ([Fetch header rules](https://fetch.spec.whatwg.org/#concept-header-value)). The approved producer's raw-header tests remain separate.

A valid header <=30000 plus transit can already be too old to display: that is a valid Board response with locally expired metrics, not invalid JSON. Contradictory body/header is a contract failure and clears retained metric eligibility. The same immediate masking applies to malformed/absent age and unverifiable local time; do not recover an old snapshot from a rejected response.

## Scheduling and lifecycle realization

**S03-R02, PROPOSED**, implements established 5 s/no-overlap/no-retry and approved P-05 lifecycle rules. One controller owns clock, timer, lifecycle generation, attempt ID and active reader/controller. Inject these dependencies for tests; do not expose test controls in production globals.

- On visible initial mount, issue the first attempt immediately (a same-turn cancellable microtask is permitted for effect replay). Subsequent slots are mount epoch + n × 5,000 ms. Use one rescheduled timeout, not a backlog of interval events. A busy slot is skipped, never queued. After any completion/error, wait for the next strictly future slot; no immediate retry. If event-loop delay passes multiple slots, discard missed slots and arm the next future one, without catch-up calls.
- Timeout at 2 s invalidates that attempt, aborts Fetch/reader and publishes timeout once. Keep the in-flight permit until reader/request cleanup settles; generation/attempt checks prevent late publication. Cleanup does not create a provider failure. Do not start a second active reader while cancellation is settling. A pathological never-settling test transport cannot cause unbounded replacement work.
- Before publishing, check mounted/visible state, generation, attempt ID, deadline and local time validity again. New usable responses atomically replace envelope, issues, timestamps and age anchor; never merge nulls. A none response discards all prior metrics immediately. Old callbacks, promises and timers cannot change a newer state.
- On visibility hidden, pagehide (including BFCache) or supported freeze event: invalidate the generation/age immediately, abort the current request, clear cadence/expiry timers and suppress all metric values and live Health status. Do not treat lifecycle cancellation as Board timeout. Discard due ticks; no hidden polling. Keep only optional last-reported metadata, never a displayable anchor.
- On visibility visible, pageshow with persisted=true or resume: deduplicate overlapping lifecycle events, remain masked and arm the next strictly future 5 s slot. A pre-hide response cannot re-enable metrics, even if it completes after return. Ordinary initial pageshow must not start a second initial request. A fresh navigation has a new mount/initial attempt; BFCache restoration retains its controller but invalidates its generation. If mount epoch is unverifiable, reset cadence epoch to local now with its first slot +5 s; do not reuse freshness. No dependency on freeze/resume support alone: visibility/pagehide/pageshow and clock guards are required at every target.
- On unmount: invalidate and abort, cancel all timers/listeners. Never suppress StrictMode or retain a shared request to hide missing cleanup. A cancellable initial microtask lets setup→cleanup→setup invalidate the first scheduled launch before it runs; tests must prove a single surviving launch/timer set. If a real request started before teardown, it is cancelled/discarded; a genuine later mount starts a fresh demand, not a cache hit. React documents development-only effect replay ([StrictMode](https://react.dev/reference/react/StrictMode)).

The browser cannot undo a Health call Board already started, nor execute JS while frozen. The guarantee is no concurrent browser refresh lifecycle and no obsolete result publication, not zero historical server work after abort. Invalidate the metric visibility gate synchronously on lifecycle events before scheduling a React update (an owned hidden-container ref is a possible realization); render/use guards then enforce the same state. Verify BFCache/first resumed paint in actual browsers rather than inferring it from synthetic events.

## Freshness and view transitions

Approved math remains in [UX](ux-v0.1.0.md#scheduling-and-browser-freshness). Record paired performance.now/Date.now samples at request start, complete body receipt and display/use. For each segment use the larger nonnegative monotonic/wall delta; reject nonfinite values or any backwards reading relative to the last sample/anchor. Accumulate checked segment durations so later smaller drift cannot reduce the bound. No comparison with Pi wall timestamps.

At use, conservative age is header age + entire request duration + elapsed since body receipt, including parse/validation/React preparation. A post-parse sample also enforces the request deadline. Forward wall jumps may expire early; backwards/unverifiable readings invalidate until a new valid response with a new local anchor. For eligibility, cap the checked age accumulator at 30,001 ms before additions; any header already above 30,000 short-circuits to expired. Preserve the original header separately for metadata. Never let large ages overflow a Number sum or a timer delay; saturation is expired. A rejected/failed fetch never refreshes the previous anchor.

Arm an **independent expiry timer** for the first millisecond beyond the remaining <=30,000 ms eligibility (not just the next poll); on wake recompute, never trust the timer alone. At exactly 30,000 data is eligible; at >30,000 remove every metric/derived value and old live hostname. Recheck before every render, expansion of exact values and other use; a delayed timer may not grant extra lifetime. Use a separate at-most-once-per-second age text update while visible, without announcements per tick. Time/lifecycle invalidation cancels both timers; no old frame should be restored by a stale callback. System suspension limitations of the server's monotonic clock remain explicit in the API; the browser does not replace that server clock with wall subtraction.

Keep three dimensions, not one overloaded status:

1. Board response: initial/loading, usable, received HTTP error, network/timeout, contract error, or lifecycle-paused. HTTP error proves reachability but no usable service response; a contract failure is not network unreachability.
2. Health: available/unavailable only as reported by the latest usable envelope. After a failed refresh, expiry or lifecycle invalidation show unknown/last reported with its timestamp, never an old live available badge.
3. Metrics: current/partial/stale/no presentable data, with independent local eligibility. Transport or Board HTTP error may retain a previously eligible view as explicitly stale; contract/age/clock/lifecycle error masks immediately. No usable view means no metrics. Valid Health-unavailable/none is Board reachable. Recovery requires the next usable response and restores only that response's data.

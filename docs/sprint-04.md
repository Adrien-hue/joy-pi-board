## R02 — Deterministic static compression proposal

**APPROVED S04-R02; implemented static-only extension.** Precompress index HTML, JS and CSS at build time with **gzip level 9**, using the already pinned Node 24.21.0 built-in zlib (record and enforce its actual zlib identity). Fix mtime to zero, omit source filename/comment and record gzip header/OS byte policy. Byte-compare repeated compression under the locked build environment. Keep original identity bytes alongside gzip. Use a generated URL/representation manifest, embedded before Go compilation, with original MIME, sizes and SHA-256 for both forms; decompress every gzip during build verification and compare exactly to identity. No compressor executable, on-demand compression or runtime decompression is required.

Prefer gzip only for this release; Brotli adds no demonstrated need. Precompute all eligible text representations even if a tiny asset is larger; this avoids a runtime threshold and keeps inventory simple. Binary assets, if added, require an explicit inventory policy and retain identity at minimum. Exclude test harness, fixtures, source maps and reports from embed. Startup may validate the bounded manifest inventory; it must still meet the 2 s readiness budget. Missing/corrupt representations fail build verification, not a silent filesystem fallback.

Proposed negotiation follows [RFC 9110 Accept-Encoding semantics](https://www.rfc-editor.org/rfc/rfc9110.html#section-12.5.3), with the following explicit local tie/error choices:

| Request condition | Proposed static response selection |
|---|---|
| Header absent or empty | Identity (absence permits other codings, but Board chooses identity; empty requests no coding) |
| Nonempty valid list | Combine repeated field lines; case-insensitive coding tokens; default q=1, valid q in 0..1 with at most three fractional digits. Unsupported codings are ignored for selection. |
| Explicit gzip/identity | Explicit coding wins over wildcard. gzip without an explicit entry uses wildcard q, otherwise 0. Identity without an explicit entry has q=1 unless `*;q=0` excludes it. |
| Both acceptable | Highest effective q; positive equal q chooses gzip. `gzip;q=0.5, identity;q=1` selects identity; `gzip` selects gzip at the tie. |
| Duplicate coding entries | Proposed conservative minimum q across duplicate entries, including q=0; test this policy explicitly. |
| Malformed q/list/unsupported parameters | Safe 400 after existing route/method/request-validity checks; no reflection of the supplied header. This is a new proposed static-header policy, not existing behavior. |
| No stored representation acceptable | Bodyless **406**, Content-Length 0, no Content-Encoding; no forced identity when forbidden. `br, identity;q=0` fails; `*;q=0, gzip;q=1` selects gzip. |

For successful GET/HEAD: retain MIME of the original URL (`text/html; charset=utf-8`, `text/javascript; charset=utf-8`, `text/css; charset=utf-8`), set `Content-Encoding: gzip` only for gzip, omit it for identity, set `Vary: Accept-Encoding` for both, and exact selected representation `Content-Length`. HEAD selects the same representation/headers as GET and sends no body. Preserve no-store for **all** resources to avoid an additional cache-policy change; no ETag/Last-Modified/304/range/206 support. Conditional and Range headers continue to yield complete selected GET representations.

Keep admission → exact route → method → request validity → representation selection. Unknown routes stay 404, methods 405/Allow, invalid query/body 400, shutdown/capacity 503. Never serve `.gz` storage URLs, manifest files, directory listings, encoded aliases or an index fallback. Route lookup must use the public manifest rather than arbitrary embedded-file existence. Errors remain uncompressed, no-store and sanitized; if identity is explicitly forbidden, preserve the earlier error status but omit its body. 406 itself is bodyless. Clear representation/age headers on failures; retain security headers and Vary on negotiation-dependent outcomes. Add tests for 400/404/405/406/500/503 and HEAD suppression without contacting Health.

Preserve the current CSP verbatim, local external JS/CSS and no remote resource. **Keep `/api/v1/overview` identity and no-store, with its existing routing and envelope unchanged**, and keep Board→Health identity. The S03 consumer rejects other Content-Encoding values. R02 applies to static routes; it does not add API negotiation or silently change the consumer. Any API compression need must be demonstrated and submitted as a separate producer/consumer contract decision before implementation.

The historical corrected S03 report records **79,522 bytes offline gzip JS+CSS**, **79,817 offline gzip static resources / 256,971 actual identity bytes**. It even gzips the sampled overview for a preliminary total. Those values do not establish future transferred bytes. Candidate measurement must count gzip static bodies actually received **plus identity first-overview bytes**, not reuse the historical all-gzip total. Use a raw HTTP client with transparent decompression disabled for wire-body hashes, and a cold real browser for the request inventory; Fetch-decoded body length is not compressed transfer length.

## R03 — Measurement protocol and overhead seam proposal

**APPROVED S04-R03 / P-06 protocol.** The existing [performance protocol](validation-v0.1.0.md#proposed-reproducible-performance-protocol) supplies durations/statistics; the following consolidates it without changing any budget. External measurement tools may observe process/kernel counters; Board gains no `/proc`, `/sys`, command or sensor collection.

| Established budget | Proposed measurement / retained oracle |
|---|---|
| Board process RSS ≤50 MiB | Sample every 1 s, all Board threads in the same process; after warmup use maximum sample, also report median/p95/max and trend. Do not include Health, browser or journal RSS. |
| No-client CPU ≤1% of one core | Health running, no browser/probes during measured phase; 2 min warmup + 10 min measurement; zero autonomous Health attempts. |
| One-client mean CPU ≤2% of one core | 2 min warmup + 10 min, one scheduled overview every 5 s (120 measured starts); no overlap. |
| Ten clients every 5 s | Separate staggered 0.5 s offsets and synchronized runs, each 2 min + 10 min (1,200 scheduled starts). No nominal skips/Board errors/unbounded queues. Record CPU without adding a ten-client cap. |
| Readiness ≤2 s | 20 fresh starts each with Health absent and present; external monotonic spawn-to-successful `/` and every required embedded asset, probes every 20 ms. Also measure systemd start request to HTTP readiness separately. |
| Shutdown ≤5 s | 20 idle and 20 in-flight timeout trials, monotonic SIGTERM-to-exit; include real unit stop observation. Record forced exits/orphans as failures. |
| Board overhead ≤50 ms p95 | ≥200 requests at 5 s after 2 min warmup, single client/no shared flight, real Health and controlled responder reported separately; proposed seam below. |
| Nominal overview ≤500 ms p95 | One-client and proposed per-client/aggregate ten-client gates; dispatch to full body receipt/validation on external LAN client. Retain server timing separately. |
| Immediately detectable refusal ≤250 ms p95 | Verify loopback listener refusal, not packet drop; ≥200 requests at 5 s after 20 excluded warmup attempts; valid HTTP 200 with connection_failed. |
| Global Health deadline 1 s | ≥30 attempts per controlled delayed-header, stalled-body and progressing-body mode; no reset/retry. Record deadline-to-cancellation and total client duration separately. Proposed ≤100 ms observation tolerance is not a changed timeout or a refusal allowance. |
| Compressed initial JS+CSS ≤250 KiB; all initial resources ≤500 KiB | Actual cold initial request inventory and selected gzip bodies, first API response identity; include all essential chunks/modulepreloads, HTML and any images/fonts/icons. Report identity fallback sizes separately; it has no newly invented compressed budget. |

CPU percent = `100 × delta(process user+system CPU seconds) / delta(monotonic wall seconds)`, **one-core denominator**, never divided by four. Use PID plus process start identity, record restarts, counter resolution and sample gaps. Collect 1 s intervals and full-phase mean, not the average of irregular percentage samples. Stable RSS sample maxima do not prove absence of sub-second spikes; retain startup peaks separately. No throttling/quota is used to manufacture a passing CPU number.

Warmup is fixed before the run and retained raw with an excluded label. For each measured latency population, sort N and use nearest-rank p95 at `ceil(0.95*N)` (1-based), no interpolation. Report N/min/median/p95/max, every planned/actual start, late/skipped starts, HTTP/transport/contract/provider outcomes and timeout counts. Keep error durations and censored timeouts in raw records; do not calculate a success-only PASS while hiding failures. An incomplete nominal population is invalid/FAIL until explained and repeated; retain the failed run. Record phase means/trends, configuration, Health identity, load schedule, environmental interference and collector versions. Do not remove busy samples post hoc. Fault/recovery phases remain separately labeled, including RSS/log behavior during prolonged Health absence and recovery.

Use remote clients/load generators so their work does not inflate Board process measurements. Freeze external observer tooling/configuration and record its overhead/resolution; no timer synchronization across hosts is used for duration subtraction. For resource size, count each initial URL once until first usable overview, exclude headers and later polls, include complete and partial fixture cases plus maximum accepted payload stress and actual real-Health initial response. No lazy-loading essential content to avoid the budget. Save raw encoded bodies/headers, decoded hashes, HAR/request inventory and manifest comparison.

### Measuring overhead with current code

Current `health.Client.Fetch` combines network and `healthschema.Decode`; subtracting all of Fetch would incorrectly remove Board validation cost. Client RTT minus a separate direct Health request, or subtraction of two p95 values, does not isolate the same request's overhead. Historical test hooks (`beforeFinalize`, `afterAssemble`, clock/barrier seams) are not a delivered diagnostic feature.

The approved **bounded opt-in diagnostic mode, disabled by default**, is implemented in S04-03. Compile it into the same candidate that will be packaged and accepted. It records monotonic handler entry/return and that request's associated flight network interval from immediately before HTTP Do (including DNS/dial) to complete bounded body receipt/close, **before validation**. For each successful unshared request, compute `handler_elapsed - associated_upstream_network_elapsed`; do not subtract quantiles. Record outcome and shared/cancelled flags; disallow shared-flight samples for this gate instead of attributing the entire flight to a late waiter.

Normal CPU/RSS/journal gates run with diagnostics off. The timing record enqueue occurs after the timed handler interval; report that excluded reporting cost and its effect using paired runs rather than claiming a perfectly cost-free observer.
